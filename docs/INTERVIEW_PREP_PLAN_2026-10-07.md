## Implementation and dependency analysis

The current prep CTA expands a general checklist. Replace it for versioned tasks with a dedicated Premium `/interview-prep` workspace, using the existing opaque action keys, authenticated queue and explicit completion banner. Legacy/unversioned tasks retain their existing checklist. A user must choose a saved resume explicitly, paste the actual posting and select one to five verbatim responsibilities/requirements to practice. Do not guess which saved posting or which of several resumes belongs to an interview. No default is required or silently selected. Keep reading and rehearsing available after preparation is marked done while the interview source is current; completion still requires an open action. Marking done must not destroy access to the notes just written.

Add owner-authenticated, Premium-gated context and practice endpoints under the existing suggestions router. Resolve the current open or completed interview action for reading/practice, then re-read its exact owned thread, anchor and application links. Refuse missing/reassigned/closed/terminal/cancelled/overlarge or ambiguous evidence. Return a content fingerprint of the relevant current source rows and application state; practice generation must revalidate it to reject a changed invitation even when the queue's existing version did not change. GET only reads source data; existing access middleware is reused. No database migration, new dependencies, OAuth scope or model/Gmail call is needed.

Produce a deterministic practice pack with exact posting quotes, possible resume excerpts based on meaningful word overlap, structured situation/responsibility/action/result answer prompts, and questions to ask the interviewer. Describe excerpts as possible examples to review, not proof of qualification. Missing overlap is not evidence of missing experience. Eligibility lines (licences, credentials, education, experience thresholds, legal/work requirements) receive factual clarification prompts, not invented experience or resume-edit advice. Questions are practice prompts, never predictions or generated personal answers. Let the user edit rehearsal notes; preserve input, pack and notes by owner/task/version in the existing in-memory session cache. Reload/logout clear them; do not advertise persistent or cross-device saving.

Show stored invitation evidence, cancellation/change recovery and explicit date/time unknowns. Follow the repository's floating-calendar-time convention; do not shift a date-only or timezone-unknown invitation into the viewer's timezone. Keep the Gmail source link visible. A rebuilt pack with changed inputs requires explicit note-reset acknowledgement so prior notes are not silently lost. Opening, building, editing and copying do not complete a task or send mail.

Completion review: the interview workspace banner shares the source query and enables completion only after source verification. Add an optional `sourceVersion` to the completion request, requiring the opaque task/version pair when supplied. The server reuses its already-derived queue, rereads the invitation/link/application state and rejects a changed source before persisting completion. Other workflows and old clients retain their existing request shape. This is an additional preflight on a user claim, not a transaction freezing incoming mail or proof of preparation; a later invitation still requires review. No new database field or automatic retry is introduced. Tests must prove stale fingerprint/cancellation/ownership failures make no completion write, and a current fingerprint follows the existing persistence path. Rollbacks must retain this supplied-version check as well as existing draft/outcome guards.

Import visibility review: syncService stores hidden rows before publishing visible evidence, and searchSignalsLoader reads visible rows. Preparation must exclude hidden source rows (legacy null visibility is treated as visible); a hidden/deleted anchor cannot fall back to another email. Hidden outcome rows are not treated as published terminal evidence. Test this boundary to avoid displaying partially imported content.

## Failure, edge, security, async, UX and operations review

| Area / failure mode | Impact | Mitigation | Graceful fallback |
|---|---|---|---|

| Failure: queue, application/email links, decryption or resume store unavailable | False readiness or another conversation used as replacement. | Validate envelopes; fail closed on storage/decryption errors; never substitute another thread/document. | Retry source load; keep local inputs/notes; no practice or completion claim. |
| Edge: malformed/duplicate keys, empty/too-large text, forged focus quote or archived resume | Crash, excessive work or unsupported advice. | Validate exact key pair, UUID and text limits; one to five unique focus quotes must be present in posting; bounded source reads and output. | Specific validation/reselection response, inputs retained. |
| Identity: reassignment, multiple application links, deleted anchor, closed/terminal/cancelled role | Prep is attached to an unavailable or different opportunity. | Revalidate queue plus owned thread/link/app state; latest schedule event wins; fingerprint current evidence, reject stale request. | Review Next Actions/Gmail; no automatic identity repair or replacement. |
| Privacy/security: foreign IDs, HTML/instruction-like source text, account switch or logged evidence | Inbox/resume exposure or fabricated advice. | Owner predicates; render text only; no model execution, content logs or browser-storage persistence; account-scoped cache/remount. | Refuse foreign/deleted source; discard late response; original text remains user-reviewable. |

## Acceptance

Staged acceptance found an integration defect the mocked done-action test did not cover: opportunity deduplication discards completed interview preparation when an open reply replaces it. Preserve only completed, still-generated interview prep candidates in the queue history alongside the deduplication winner. Do not create historical tasks from persisted rows, change active-task priority, revive cancelled/terminal/past invitations or alter source ownership. Dependency: existing generator status resolution and queue buckets; no schema/API change. Failure impact is inaccessible rehearsal notes after completion; mitigation is retained done history plus a real generator/feed regression; fallback remains fail-closed source review if the current invitation cannot generate. Async/privacy boundaries stay unchanged, with exact owner/source preflights. Performance adds at most the already generated completed prep rows to history, not extra database reads. Deploy backend first, rerun signed-in post-completion acceptance, preserve all guards on rollback, and verify the done task does not appear in active buckets. Record this correction separately from the initial implementation.

- Nurse, receptionist, warehouse, teacher, technical and career-change inputs produce only verbatim source excerpts and practice prompts; absent resume overlap never says a skill is missing.
- Pending licences/credentials receive factual eligibility clarification without resume-edit advice or a claim the credential is held.
- No default or several resumes requires an explicit choice; archived/foreign/unreadable resume cannot fall back to another.
- Changed/rescheduled/cancelled/closed/terminal/reassigned/deleted/ambiguous source fails honestly without writes; stale fingerprint cannot generate.
- Inputs and notes survive navigation within the stated editing session, separate per task and account; no late response crosses owners or overwrites edits.
- No implicit completion/send; narrow/desktop browser flows and real signed-in synthetic backend acceptance pass before publication.

This adds a grounded rehearsal workspace, not simulated interviews, predicted questions, an AI grading system or persistent cross-device notes. The full resume workspace and atomic close-plus-queue completion remain separate milestones.
