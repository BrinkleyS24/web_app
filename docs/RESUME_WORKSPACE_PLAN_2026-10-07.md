# Resume compare, edit, save and use

Status: implementation and local verification complete. Backend source `fa31186` is live as `applendium-backend-resume-fa31186` and passed staged/public signed-in resume acceptance with cleanup. Web publication remains pending. The review below was written before source changes.

## Implementation and dependencies

Keep existing basic resume management available to authenticated free and Premium accounts; Premium outcomes/health retain their existing gates. Add an owner-only, no-store `GET /api/resumes/:id` using the existing encrypted-document reader, with UUID validation, readable/bounded text and a deterministic document fingerprint. Foreign/archived/missing documents return 404, unreadable text 422, storage errors a sanitized retry response. Static routes stay before `/:id`. No schema, dependency, OAuth, model or email changes.

Extend the library with an accessible editor and a two-document comparison. Fetch selected documents only; compare actual wording, not causal effectiveness or invented scores. Plain text preview/copy/download is the actual analysis text, not a formatted Word/PDF export. Editing saves a separate named version through the existing idempotent create RPC; original text, identity and outcome attribution stay intact. The name and default option are explicit; edit saves default to `none`. The existing transaction atomically handles an opted-in default replacement and serializes account writers. There is no in-place text update or new lineage table. A source snapshot is a starting point for the user's independent edited document, not a claim its original remains current. If it disappears after loading, retain edits with that distinction and require a separate explicit new-version save.

Preserve editor state by account/source in existing tab-memory sessions (30-minute inactive lifetime; reload/logout clear unsaved work). Preserve retry ID with the exact normalized name/text/default payload. Save errors retain input; uncertain responses reuse the same ID. After create success, retain the receipt and verify the new document by ID and exact trimmed content before offering use/export of the saved version. A failed read after a confirmed write offers verification retry, not a second create. Changing inputs after a save requires another explicit version save. Do not reset an edited draft on background source refresh; reset/discard is explicit and confirmed.

Add a validated `resume=<uuid>` handoff to Apply Gate, preserving only the existing opaque action/version pair. An explicit handoff outranks the default; invalid, duplicate, foreign/archived/unavailable choices block checking until the user selects a valid document, with no silent fallback. Keep the job title/company/URL/posting/apply style in the existing account/task-scoped memory cache during library navigation. Recheck the role explicitly after edits; saving/opening/copying never submits an application, reruns AI or marks a task complete. Interview prep already requires explicit selection; invalidate its resume list when saving without silently replacing its selected document or notes.

## Risk and operational analysis

| Area / failure mode | Impact | Mitigation | Graceful fallback |
|---|---|---|---|
| Dependency: existing RPC absent or encrypted text unreadable | Cannot save or preview accurately. | Reuse deployed transactional create; validate owner, readable bounds and envelopes. No fallback writer/decryption guess. | Keep edits, report retry or reselection; do not show blank text as a valid resume. |
| Integrity/schema: editing historical text under the same ID | Past checks/outcomes appear to describe new wording. | Save new ID only; do not modify text or attribution; no migration. | Original remains usable, new version starts with its own record. |
| Failure/retry: POST succeeds but response/read is lost | Duplicates or falsely reported saved state. | Stable request ID per exact payload, persisted receipt, separate verification retry; no automatic mutation retry. | Keep input and uncertainty visible; retry same save or verification, never silently create again. |
| Edge: invalid/duplicate UUID, archived/foreign target, malformed envelope, oversized input | Wrong document, content leak or crash. | Strict route/client identity validation; 50-50,000 text/120 name bounds; owner and active predicates. | Honest unavailable state; no default substitution. |
| Race/async: source renamed/archived, two tabs changing defaults, double-click, late response/account switch | Lost edits, misleading identity or cross-account UI. | Immutable edited snapshot, explicit default choice with account-lock RPC; synchronous submit guard; owner-keyed remount, late-response guard; no source-refresh overwrite. | Retain draft, require save/reselection; receipt remains tied to exact payload. Last explicit default choice wins; do not promise compare-and-swap semantics. |
| Privacy/security: decrypted text in URLs/logs/browser storage, HTML in content | Private information exposure or injection. | URLs contain only UUID/opaque task keys; render text, never HTML; no content logs, localStorage or model calls; account-isolated memory. | Refuse malformed/foreign reads; ignore late results; memory clears on logout/reload. |
| UX failure states: edited text mistaken for saved version, navigation loses posting, discard/reset loses work | User checks wrong resume or loses meaningful work. | Separate draft/confirmed-save states, verify server text, explicit discard/reset, named handoff and remembered posting. | Disable use until confirmed, keep edits and posting; clear session lifetime disclosure. |
| Performance/backpressure: loading all text, quadratic diff or repeated model checks | Slow library, memory/CPU growth or expense. | Selected one/two bounded documents only; linear line-count comparison with limited summaries; exact text panels; no model check on save. | Cancel/reselect or retry a failed read; oversized text refused; inactive cache expires. |
| Deployment/rollback: new UI reaches older backend or regresses prior guards | Preview 404, stale prep/draft/outcome mutation accepted. | Additive route; backend first, zero-traffic signed-in acceptance, public acceptance before web push. Preserve both flags and Firebase version 2. Align images without executing jobs. | Candidate stays zero traffic on failure; reviewed web rollback or forward fix retaining all prep/draft/outcome guards. |
| Observability/testability: mocks conceal wrong-owner read or saved content | Incorrect release or privacy regression. | Service/route tests; UI save-timeout/read-failure/account/navigation tests; mobile/desktop browser flows; real signed-in synthetic reads/create/retry/default/ownership/cleanup. Low-cardinality status/code logs only. | Block publication on failed acceptance, report verification boundary; never inspect customer resume/inbox for testing. |

## Acceptance

Two saved versions with no default can be opened and compared without writes. Editing creates a new ID, exact confirmed text, original unchanged; retry produces the same ID and never reapplies a prior default decision. A verification outage keeps receipt/draft and retries reads only. Copy/download reflect the confirmed saved text. Explicit use selects that exact available version over another default; missing/invalid links never substitute a default. Posting and opaque action context survive library navigation; no automatic analysis/submission/completion. Unsaved work stays separate by account/source and survives navigation within the stated lifetime. Comparison/edit/export fit mobile and desktop, with keyboard labels/focus and honest loading/error states. Staged/public synthetic acceptance and cleanup precede publication.

Limitations: text workspace and plain-text export, not a layout-preserving file editor; unsaved drafts remain tab-memory only. No causal ranking, new AI rewrite, historical backfill or automatic reassignment to new versions. Existing health/outcome semantics remain unchanged.
