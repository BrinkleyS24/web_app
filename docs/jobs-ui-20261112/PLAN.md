# Jobs UI improvement plan — before product code

Acceptance: on return with saved preferences, useful roles and their specific remaining fit questions lead. Setup remains explicit about work location and optional target titles. Recommended, review, older, excluded and already-applied distinctions and all source evidence stay intact. Exclusions/history must be accessible without competing with daily opportunities. Completing a real operation must yield a visible, persisted state: preference save/refetch, application-history retry/reclassification and restored results after discarding edits. No matching, eligibility, date, source, ranking or attribution-policy changes.

Baseline read-only production inspection: four review roles, zero supported roles in the current feed, 22,850 exclusions. First role heading y=873 at 390px and y=946 at 320px. Settings, two update concepts, freshness, five status controls and repeated caveats precede it. First review card leads with employer-assessed communication before actionable scope/on-call questions. Actual data and screenshots remain private.

Implementation: keep existing queries, cancellation, version/fingerprint bindings, auto polling, application-aware projection and stateful preferences form. Condense return-state preference summary. Keep Matches / Needs review / Older as primary navigation; put Already applied / Excluded in an explicit secondary disclosure with direct empty-state access. Move routine application recheck/collection detail into the existing coverage disclosure; retain a visible retry if history fails. Present one original actionable review note before generic assessment notes; preserve all original notes and exact requirement/evidence passages in disclosures. Keep historical counts/limits and stale/partial/pending states truthful. Add an exact saved-resume handoff without changing which resume qualifies.

Dependencies: current saved preferences, resume list, feed/background status and read-only application-status APIs; React Query owner caches; existing safe links and requirement rendering. No new service, database migration, preference field, matching extraction, resume parsing, source supply or AI call. Only presentation helpers and existing form/state corrections justified by observed behavior.

Failure / impact / mitigation / fallback:
- Controls bury the role -> customer cannot find actionable value -> compact saved summary, primary opportunity navigation, secondary diagnostic disclosure -> setup/error/pending remains explicit if no roles can be shown.
- Generic caveats precede the real review issue -> wrong next step -> choose an existing non-interview-assessment note verbatim, not generated eligibility advice -> if no actionable question exists say it was not supplied and retain original evidence/posting.
- Hidden secondary views become unreachable -> lost history/exclusion evidence -> explicit labeled disclosure, reveal selected secondary view, direct empty-state link -> primary section always available.
- Missing evidence confused with blocker or interview considered qualification -> false reassurance/exclusion -> preserve decisions, blocking flags and original evidence/categories; history remains ordering evidence -> no promoted match or inferred submitted resume.
- Unavailable/stale/partial feed looks like no market -> false zero -> preserve existing results guards and progress/error states, visible partial scope -> retry/automatic polling without fabricated zero counts.
- History lookup fails or changes -> duplicated applications or hidden jobs -> preserve application-aware identity references and owner checks; failure visible with retry -> keep qualification results with uncertain application status disclosed.
- Pending or failed preference save clears edits -> lost intent/wrong jobs -> retain existing expectedVersion, dirty-state withholding and cancellation -> retry current draft or explicitly discard; saved response must yield restored matching for that exact resume/version.
- Background refresh moves a reader's selected section or closes evidence -> lost place -> preserve explicit/automatic chosen tab and stable card keys -> update counts without changing the selected section.
- Two refresh operations are confused -> unnecessary work -> routine application retry under coverage with explanation, failure retry next to warning -> default auto checks remain active.
- Invalid posting or missing resume identity -> unsafe/misdirected navigation -> reuse HTTPS credential-free posting URLs and exact validated document links -> no substituted document or unsafe posting link.
- Long titles/notes/locations and narrow failure panels -> overflow or unreadable text -> min-width/wrapping and shared mobile error layout; keep all original text accessible -> scroll only where necessary, no evidence truncation masquerading as completeness.
- Account/source switch races -> prior-account or prior-resume cards -> leave query keys, cancellations and dirty guards intact -> hide incompatible/stale results until current source is available.

Security/privacy: React text rendering, safe external links, owner-specific caches and exact document references. No real preference/application/source writes in the audit; application-status POST is read-only. Private actual-account bodies/captures stay local. Fictional stateful fixtures cover saving/retries and history changes. Existing GET feed may prepare private derived results as the product normally does; no new worker/configuration change is introduced.

Performance: reduce initial visual controls, not source checks or coverage. No extra request/fan-out; unchanged bounded rendering and polling. Avoid new derived counts that imply a global inventory or qualification. Test computation helpers independently with source preservation assertions.

Verification: predefine and test complete journeys, not just messages. Stateful preference save then reload; discard dirty edits; switch sections/background refresh; open full long notes; source blockers vs missing evidence; pending/stale/partial/unavailable; already applied and possible duplicate; history failure then retry moves the exact role; optional target clearing; archive/default changes; safe links/exact resume. Run existing Jobs/application/background/discovery tests and browser cases, new focused fixtures at 320/390/768/1440, actual-owner read-only before/after, TypeScript/build/full web regression. Grades remain scoped engineering assessments; no automatic A from passing tests or the thin live sample.

Deployment/rollback/observability: frontend-compatible candidate, separate from the current Resumes release. Commit review artifacts with source/count parity, viewport measurements, request statuses and client errors, without private passages/tokens. No backend or stored-data rollback. Any later release must build frozen source, stage normally authenticated behavior and preserve serving configuration; rollback to the previous web deployment. Dashboard remains last.
