# Apply Gate UI/workflow plan before product code

Acceptance: checking a new role starts with the selected resume and posting text/public link, not a long optional form beside an empty result. Saved checks have a separate, clearly scoped view. Form drafts/results and pending operations survive view changes. A completed choice is acknowledged only after a positive save response. Starting another role clears the prior posting while retaining resume/apply-style choices. Checking a version never claims it was submitted. Original verdicts, hard blockers, requirement alternatives, calibrated-vs-fit-based risk, source quotes, outdated markers, exact source IDs and grouping remain unchanged.

Baseline: actual-owner read-only serving inspection places Check this role at y=1145 on 390px and y=1202 on 320px. The initial desktop form also extends beyond 1000px and has an unused result column. Five saved posting cards compete with the form. Source review found Review another role only clears result/confirmation, leaving the old posting; selected-resume help wrongly says it is recorded as sent; percent/stage progress is time-estimated rather than server-observed; false save acknowledgments and unsaved-ID fallback can claim recorded choices.

Implementation: URL-backed Check a role / Saved checks views, mounted for draft/pending continuity. Load history when requested, needed by a linked source or by a current result, with explicit loading/error/empty states and access to all returned grouped postings. Preserve exact source-check handoffs; a successful saved-posting recheck opens its result. Keep resume/text/link primary; put optional title/company/apply style and wording lifecycle explanations in a disclosure. Show no empty result column before a check. Keep call → qualification warning → next step → decision recording → evidence details. Collapse optional networking guidance. Use an indeterminate pending state with observed elapsed time, not invented completed stages/percentages. Capture analysis payloads atomically; identify changed inputs and disable recording an old result as if it were the current draft. Serialize analysis/recheck/action writes on this workspace while leaving read-only view switching available. Require success acknowledgments for recorded choices; refuse a claimed save for an unsaved check. Fresh-role action clears posting/source-task context deliberately and keeps chosen resume/style in the existing owner-scoped draft session.

Dependencies: existing Firebase/plan/AccountQueryScope, resume/profile queries, analyze/recheck/action/history APIs, source-version/decision presentation, immutable resume editor links, draft-session lifecycle, existing cross-feature invalidation. No model/provider, schema, scoring, matching, source fetching, Chrome extension, billing or qualification-policy changes. Backend recheck identity remains authoritative; do not invent posting text or substitute a resume/source version.

Failure / impact / mitigation / fallback:
- Optional fields/history bury the useful task -> customer cannot start -> compact primary inputs and separate views -> required resume setup/errors remain explicit, evidence stays accessible.
- History failure/malformed response looks empty -> false lack of saved checks -> validate basic success/list shape and show retry -> keep new-check draft usable; do not render a zero-history claim from failure.
- History limited/grouped/source link silently hides records -> lost context -> show loaded/grouped count, More checks and exact named source first -> disclose loaded scope rather than claim all-time completeness.
- View switch/recheck loses drafts or request state -> duplicated/lost work -> keep views mounted and preserve URL task/resume context -> restore the same draft/result; no automatic task completion.
- Completed workflow retains old posting -> accidental repeat check -> explicit fresh-role reset of title/company/text/link/result and obsolete task/verdict URL -> retain selected resume/style, saved check remains in history.
- Time-estimated stages imply completed server work -> false progress/trust -> indeterminate pending plus actual elapsed time -> no verdict/percent until a response exists, honest retry on failure.
- User changes inputs mid-flight or sees old result under new inputs -> wrong decision association -> immutable dispatched payload, disabled editing during operation, source-change warning afterward -> rerun before recording current-input advice; original result/evidence stays identifiable.
- Concurrent analyze/recheck/action callbacks affect a different check -> wrong feedback/confirmation -> workspace operation lock and pending guards -> keep current result, require completion/retry before another writer.
- False acknowledgment/no saved verdict ID claims a recorded choice -> invented persistence -> success true required and unsaved-check action refused -> clear not-saved message, original posting/result retained for retry.
- Applying intent interpreted as submission/resume attribution -> inflated history -> truthful labels and existing application-level confirmation link -> no submitted version inferred or auto-confirmed.
- Hard gates/unknown evidence/preferred alternatives collapse into generic advice -> false recommendation -> leave authoritative presentation and QualificationEvidence intact -> missing/unsupported decision remains degraded; no fallback fabricated verdict.
- Long fields/phone/reduced-motion or lost focus -> inaccessible next action -> shared wrapping/min-width controls, keyboard view navigation, focus fresh form/pending panel without scroll-on-every-tick -> preserve text and explicit errors.
- Source/archive/expired-version link changes -> different document or posting checked -> retain exact IDs and backend recheck semantics, review response source name -> no default substitution or inferred source text.

Privacy/security: normal authenticated owner reads only during live inspection. Guard analysis/action/recheck/profile/resume writers, no real feedback, email, billing, preference or resume mutations in browser audit. Use persistent fictional API fixtures for full journeys; no live AI/provider spend. React text and existing posting URL safety remain in place. Private account inputs/images stay local; publish synthetic captures and sanitized counts only.

Performance/async: history deferred for a blank new check; no new source/API fan-out. Scope operations to immutable payload/check ID; retain version and owner boundaries and existing invalidations. Timers clean up; no pretend streaming. Failure must preserve inputs/result rather than clear them. Recheck/history writer semantics are unchanged, with acknowledgment guards at presentation boundary.

Verification: original actual resume/saved checks and source passages read-only; baseline/final at 320/390/768/1440. Stateful new check → failed action → retry → saved history → reload → fresh-role reset; URL-only and text-only input; optional metadata/styles and exact resume; explicit source-check recheck and failure; edited-input mismatch; pending view switch and concurrent-operation prevention; false success/unsaved verdict; no-resume/archive/profile failures; hard degree/experience blockers, preferred gaps and authoritative display parity with existing extension fixtures; loaded history grouping/show-more; no invented percentages. Run existing relevant unit/browser/contract suites, type/build/full web regressions. Grade scoped observed workflows, not a new AI/matcher/production-capacity certificate.

Deployment/rollback/observability: frontend-only local candidate after Jobs rollout, no migration or backend change. Commit review evidence and measured workflow results, not private data. Any later deployment uses frozen source, normal-auth draft/serving checks and pinned rollback; source data needs no rollback. Observe current endpoint failures, acknowledged state transitions, client errors/overflow and dispatch payloads in fixtures without logging resume text/tokens. Dashboard remains last.

Observed history refinement before code: live read-only phone inspection still shows a roughly 1000px first saved card and squeezed role names beside badges. Keep role/employer/date/resume/decision and stale-check notice visible. Fold non-outdated evidence and decision recording into one disclosure, open for an explicitly linked source. Risks: hidden evidence/action -> obvious Review evidence and record a choice summary plus visible decision; false historical freshness -> latest check date stays visible; phone squeezing -> stack header badges below role. Preserve all original quotation/action contracts and test them by opening the disclosure.

Response-boundary refinement before code: HTTP 200 can still contain success:false. Analysis/recheck must reject this envelope instead of replacing the previous result with a failed response. Impact: false result or lost context. Mitigation: require success:true at the request boundary. Fallback: preserve the posting and previous result, show retryable analysis/recheck error. Add a negative-envelope regression test; no server contract change.

Reload/source refinement before code: a successful recheck uses view=check plus verdict=<new-id>; after reload its in-memory result is gone, so that URL must reopen the named saved source rather than a blank form. Compute the view after result state is known, and clear an abandoned verdict parameter only when the customer explicitly chooses a new check without an in-memory result. Impact/fallback: no lost source identity; missing source uses existing unavailable-history state. Clear previous analysis errors when starting a serialized recheck so old failures cannot contradict its new result. Verify recheck -> reload -> named source and explicit new-check navigation.
