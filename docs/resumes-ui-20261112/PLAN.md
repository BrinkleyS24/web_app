# Resumes UI plan before product edits

Acceptance criteria: Library opens with saved versions and their immediate tools, rather than attribution counts or outcome analysis. Outcomes & submissions is an explicit view with direct confirmation access and clearly scoped role comparisons. Wording comparison is named separately. No default/checked version becomes a confirmed submission; pending/unknown/archived records and insufficient samples keep their existing meanings. Drafts, selected wording comparisons, pending confirmations and retry IDs survive view switching. Unknown or failed checks never look clean. Deep links from Apply Gate/Strategy remain usable at desktop, tablet and mobile widths.

Implementation: add URL-backed Library / Outcomes & submissions views, defaulting to Library. Preserve existing action/version/resume parameters and existing #submitted-resumes links. Keep visited views mounted to preserve drafts and pending writes; defer outcome/submission loading until requested. Move role-specific outcome comparison, record drilldowns and archived history into Outcomes; place confirmation access first, role-filter scope beside its rates, and details/history under explicit disclosures. Library retains add/edit/default/archive/Apply Gate and saved-wording comparison, with basic-check scope and clear unavailable states. Reuse immutable editor and submission components/transactions. Validate library and health reads at the presentation boundary and keep failure states independent. Bind the legacy-profile review cache to its owner; the current owner-free key can reuse prior-user cached text during a switch (fixture reproduction required, no live foreign-account access).

Dependencies: existing Firebase/plan gates, resume list/health/document APIs, confirmed outcome contract and submission revision/idempotency APIs, draft-session cache, action-context links, existing cross-feature invalidation. No new API, migration, source coverage, AI call, persistent preference or Dashboard redesign. Keep the free library/default workflow available without Premium reads.

Failure / impact / mitigation / fallback:
- Mixed library/outcome purposes -> customer cannot find saved wording -> separate views with contextual labels and direct submission shortcut -> Library remains the default and usable during history failures.
- Default/checked version credited as submitted, pending counted or thin rates trusted -> false recommendation -> preserve existing confirmed-outcome validator, source data and sample thresholds -> explicit unknown/insufficient/unavailable states; no partial recommendation.
- Role filter mistaken for a filter on all confirmations -> inconsistent counts -> role scope beside comparison; confirmations explicitly list all applications -> no global attribution count inferred from a filtered result.
- Tab hides/unmounts an editor/save/selection -> lost work or duplicate request -> retain mounted visited views and existing request IDs/owner keys -> resume the same draft/confirmation or safely retry the same request.
- Account switch with global legacy cache -> another account's profile text can be offered -> owner-bound legacy key and owner-enabled reads, preserve parent owner reset -> wait for the current account's response; no inherited text.
- Malformed/failed library or health reads -> false empty library/clean flag or render crash -> structural validation and withholding cached failed health data -> retryable panel and explicit not-checked/unavailable labels; independent tools remain available.
- Changed/archived source or delayed scoreboard -> wrong history/recommendation -> keep outcome display dependent on a verified current library and preserve immutable saved versions -> no archived inference while list is unknown; keep historical credit rules untouched.
- Dismissed findings mistaken for job fit -> false reassurance -> explain basic checks' limited scope, keep original evidence and dismiss/undo controls -> do not present checks as eligibility, ATS certification or reasons for rejection.
- URL view/hash mismatch, incomplete document link or malformed fragment -> broken handoff -> explicit view routing, safe ID/fragment handling and context-preserving library links -> current-library guidance, never substitute a different saved document.
- Default/archive/create error or concurrent change -> wrong active version or hidden save failure -> preserve server atomic defaults, explicit archive confirmation, pending guards and idempotent create -> keep current document/draft and clear retry feedback.
- More/long versions or histories -> one-letter titles/overflow or overwhelming initial page -> preserve minimum widths/word wrapping, defer history, concise cards and bounded existing paged confirmations -> all source history accessible without crowding Library.
- Privacy/injection -> disclosure or executed source content -> React text rendering, owner-scoped caches, encoded exact links, private real-account captures; no real source-changing actions during audit -> sanitized reports and fictional write tests.
- Performance -> unnecessary outcome/stats/submission work before editing -> lazy Premium history reads, existing shared cache/invalidation, no per-card AI calls -> Library/health can succeed independently of history.
- Rollout/rollback -> broken shared paths or state -> frontend-only compatible changes, preserve URL contracts, frozen production build for a later release -> prior web revision, no stored-data rollback; unsaved drafts remain session-limited as before.

Verification: reproduce the legacy cache risk with synthetic owners; target lazy loading, both view routes and back/forward, editor/draft and confirmation preservation, default/archive/create error/idempotency, current/legacy/malformed outcomes, health failure vs clean, role-filter scope, archived/unknown attribution, no-default/empty/free accounts and all cross-feature links. Keep existing meaningful editor, submissions, outcome-contract and browser tests. Inspect real owner Library/Outcomes/edit/wording-compare read-only; perform mutations only in explicitly fictional browser/API fixtures. Cover 320/390/768/1440 widths, keyboard view navigation and long names. Run relevant regression/type/build checks and publish a scoped review, not a universal A from an empty screenshot.

Observability/deployment: sanitized query status/request counts, client errors, source parity and viewport measurements; private bodies/text/screenshots stay local. No new telemetry. Strategy release is separate and already verified; this task produces a committed reviewable Resumes candidate, with release status explicit. Monitor the existing read/write endpoint failures and stale-source conflicts without logging document text or tokens. Human usability, all browsers and live mutation/concurrency certification remain outside this UI review.

Post-implementation review clarification: App.AccountQueryScope already creates a new QueryClient and remounts local state when the account changes. The explicit legacy-profile UID key is defense in depth for component/shared-cache reuse. The synthetic test establishes that old global/other-owner entries cannot be offered within a reused cache; no live cross-account disclosure was observed.
